Wireflip — 修改请求，继续开发

Wireflip 是为前端开发者和测试人员准备的本地浏览器请求实验室。无需修改后端，即可修复跨域、模拟接口、检查请求改动，并复现加载或失败状态。原名 CORS Unlocker，保留原扩展 ID 和旧 SDK 桥接。

已启用规则自动运行
保存并启用的规则会自动作用于匹配的受支持页面，包括新打开的匹配标签页。可用规则分组组织配置，暂停分组或禁用规则来停止改动。请求录制独立控制：停止录制不会停止已启用的规则。升级后，2.0 中已启用的 Mock、延迟和 CORS 规则可能无需启动标签页会话就开始在匹配页面运行。

快速控制与请求检查
在 Popup 中为当前标签页临时修复跨域、控制凭证、绕过 HTTP 缓存、延迟 Fetch/XHR 或模拟失败。打开 Inspector 录制请求，检查匹配规则与已应用的改动。使用本地 JSON 模拟响应，修改请求和响应头，重定向或拦截指定请求。按页面来源、请求地址和方法明确设置范围，并在本地导入、导出规则备份。

网站改动需要你的批准
使用可选 SDK 的网站，必须先在 Wireflip 自有窗口中获得批准才能修改规则。只有你能在 Popup 中手动信任某个精确来源，让该网站以后管理它自己创建的规则；访问登录凭证仍需确认。可随时撤销信任，已保存规则继续由你控制。手工创建或旧版未标明归属的规则只能在 Wireflip 中管理。

Chrome 限制
当已启用规则、请求录制或临时控制需要调试器时，Chrome 可能显示原生调试提示。匹配页面的准备是异步的，就绪前发出的请求可能直接通过。停止录制仍会保留已启用规则，需禁用规则或分组才能停止。HTTP 缓存绕过不会清除浏览器数据，也不会绕过 Service Worker。Wireflip 不隐藏 IP，也不代理其他应用。

数据保留在本地
无需账号、原生客户端或云同步。规则保存在扩展本地存储；捕获活动保存在内存中，后台停止时清除。默认遮蔽敏感请求头，不上传流量、规则或日志。

支持英语、简体中文、日语、韩语、法语和西班牙语，以及浅色、深色和跟随系统主题。SDK 集成是可选的；现有 cors-unlocker 集成保留原托管桥接，升级 wireflip@2.1.0 前请阅读迁移指南。
