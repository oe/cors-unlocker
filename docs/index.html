Forth Intercept documentation

Forth Intercept is an in-browser proxy for developers. It changes requests inside Chrome or Firefox; it is not an IP proxy, VPN, or system-wide traffic capture tool.

Install

Add Forth Intercept to Chrome, then pin it to the toolbar. Version 2 keeps the existing Chrome and Firefox extension IDs and automatically migrates existing settings.

Firefox support is currently distributed as a beta build artifact from CI. Load the unpacked dist/firefox directory temporarily during development; an AMO-signed public build will follow separately.

Interception stops when you switch it off, close the tab, or the top-level page navigates to a different origin. Chrome Advanced mode also detaches when another debugger takes over.

Popup quick controls

Open Inspector to inspect the current tab, or use Start proxy session to begin capture. Connecting alone does not enable CORS repair: it captures traffic and applies your enabled saved rules.

Quick debug offers CORS repair, Disable cache, a 500 ms / 1 s / 3 s request delay, and simulated request failure. Delay and failure affect only Fetch/XHR requests in this tab. Enabling a quick control starts the proxy; Chrome displays its debugging banner. Allow credentials is directly below the CORS switch.

Disable cache bypasses HTTP cache for the current Chrome tab. It does not clear browser data or bypass service workers. Turning the switch off restores normal cache use. This control is hidden in Firefox.

Stop this session, closing the tab, or navigating to another origin clears these temporary controls. Existing site CORS rules are separate persistent rules and remain enabled until you turn them off. Pin named saved rules for quick access. Their switches change saved configuration; stopping the proxy does not disable saved rules, and DNR rules can continue across tabs. Saved mocks, delays, and failures need an active proxy session. Firefox CORS repair patches headers but cannot synthesize failed preflights.

Rules

A rule contains a page-origin match, request URL glob, optional HTTP methods and resource types, followed by one or more actions.

{
  "name": "Mock project API",
  "enabled": true,
  "match": {
    "initiatorOrigins": ["https://app.example.com"],
    "urlPattern": "https://api.example.com/projects/*",
    "methods": ["GET"],
    "resourceTypes": ["XHR", "Fetch"]
  },
  "actions": [
    {
      "type": "mockResponse",
      "status": 200,
      "headers": { "Content-Type": "application/json", "Access-Control-Allow-Origin": "*" },
      "body": "{\"id\":123,\"state\":\"preview\"}"
    }
  ]
}

Available actions are cors, setRequestHeaders, setResponseHeaders, redirect, block, mockResponse, delay, and networkFailure. Action scripts are validated JSON; arbitrary JavaScript is not evaluated.

Site controls

Choose Open Inspector from the popup to manage rules for the current HTTP or HTTPS page. Toggle rules or click their names to edit them directly in the side panel. New rules default to the current page origin.

Enable Advanced proxy, then reproduce a request on the page. This switch starts activity capture and applies enabled saved rules. Enable CORS repair separately in the popup, or use a saved CORS rule when needed. Select a captured request to create a Mock, Delay, Block, or Headers rule without leaving the panel. Save, trigger the request again, and inspect the recorded result.

Activity shows captured rule names and applied changes, including header before/after values, redirects, delays, and local mocks. Check against current rules explains disabled rules and mismatched URL, method, or resource type conditions; it does not reconstruct historical rule priority. Authorization, Cookie, Proxy-Authorization, and Set-Cookie values are masked.

Basic browser rules can act before activity capture, so this is not a complete network log. Use DevTools Network for detailed response and timing analysis. Recorded matches are evidence of condition matching, not proof that every configured action executed.

SDK

forth-intercept is the canonical SDK package. Existing installations can continue using cors-unlocker@0.2, which is a thin compatibility package that re-exports the same API.

pnpm add forth-intercept
import { intercept } from 'forth-intercept';

const session = await intercept.connect();
console.log(session.origin, session.capabilities);

if (session.capabilities.interception.responseMock === 'body-replacement') {
  console.log('Mocks preserve the upstream HTTP status in this browser.');
}

const status = await session.getStatus();

await session.requestCors({
  credentials: false,
  reason: 'Preview staging API data',
});

requestCors() always shows an extension-controlled confirmation and applies only to the real top-level page origin. A page cannot request changes for another origin.

session.capabilities.interception reports whether the browser supports synthetic responses or body replacement, synthetic preflights or header-only repair, reasoned network failures or cancellation, and distinct or combined Fetch/XHR resource types. Applications should use these values instead of inferring behavior from the user agent.

Create a disabled rule draft

await session.createRuleDraft({
  name: 'Simulate slow projects API',
  urlPattern: 'https://api.example.com/projects/*',
  methods: ['GET'],
  resourceTypes: ['XHR', 'Fetch'],
  actions: [{ type: 'delay', milliseconds: 800 }],
});

SDK-created rules are always disabled and scoped to the calling page. By default, the workspace opens so the user can review and enable the draft.

API surface

  • intercept.connect({ timeout? }) → InterceptSession
  • intercept.isAvailable() → boolean
  • intercept.openStorePage()
  • session.getStatus()
  • session.requestCors({ credentials?, reason? })
  • session.disableCors()
  • session.createRuleDraft(rule, { openWorkspace? })
  • session.openWorkspace()

The legacy isExtInstalled, isEnabled, enable, disable, openExtOptions, and openStorePage exports continue to call the new local bridge.

Upgrade and data

On first v2 startup, Forth Intercept reads allowedOrigins and extConfig, writes a legacyBackupV1 recovery snapshot, validates the new proxyAppState, and then uses only the v2 state. Old keys are not used as live configuration or dual-written.

The workspace imports old v1 rule exports and complete v2 exports. New exports use the v2 format.

Limitations

  • Chrome Advanced mode necessarily shows Chrome’s debugging disclosure.
  • Firefox uses blocking WebRequest and does not attach a debugger.
  • Firefox response-body mocks preserve the server’s original HTTP status and require an actual response.
  • Firefox applies CORS headers through DNR. Failed preflights still require server support; credentialed requests with custom headers must include those headers in the CORS rule’s allow list.
  • Changes affect matching Chrome or Firefox traffic, not other applications.
  • Forth Intercept does not change your public IP address or decrypt traffic outside the browser.
