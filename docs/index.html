Start with the extension

Wireflip changes requests inside Chrome and Firefox. You can repair CORS, edit headers, mock APIs and test slow networks from the browser interface. You do not need the npm SDK to use the extension.

Install

  1. Add Wireflip from the Chrome Web Store or Firefox Add-ons.
  2. Pin Wireflip to the browser toolbar.
  3. Open the HTTP or HTTPS page you want to debug, then click the Wireflip icon. The Popup shows that page’s origin so you can check the scope before changing anything.

Browser settings pages and extension-store pages cannot be intercepted. Use a normal website or your local development page.

Your first CORS repair

  1. On the affected page, open Wireflip’s Popup.
  2. Under Temporary changes, turn on CORS repair. This starts a session for the current tab. Chrome displays its standard debugging banner.
  3. Repeat the request in your application. If your application sends cookies or authentication credentials, enable Allow credentials only for a page you trust.
  4. Click Inspect and modify requests to see captured requests and their applied changes.
  5. Click Stop tab session when finished. Temporary changes reset.

Connecting a session alone does not turn on CORS repair. Enable the control explicitly. Firefox can repair response headers but cannot synthesize a failed preflight; that case still needs server support.

Temporary controls and saved rules

Temporary changes affect the current tab and reset when you stop its session, close it or navigate to another origin.

Saved rules keep their enabled state. Persistent header, redirect and blocking rules can continue across matching tabs after a session stops. Mocks, delays and simulated failures require a running tab session. A rule group pauses saved rules without changing their individual switches.

Read the extension guide for the complete workflow, including rule matching, groups, Inspector and backups.

SDK

The SDK is optional. Use it when your application needs to ask Wireflip for CORS access or prepare a rule for the user to review. See SDK integration.

Existing CORS Unlocker users can keep their SDK and hosted bridge. See the migration guide; no reinstall or settings reset is required.
