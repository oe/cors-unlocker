# Forth Intercept documentation

Forth Intercept is a Chrome-native request lab. It changes requests inside Chrome; it is not an IP proxy, VPN, or system-wide traffic capture tool.

## Install

[Add Forth Intercept to Chrome](https://chromewebstore.google.com/detail/knhlkjdfmgkmelcjfnbbhpphkmjjacng), then pin it to the toolbar. Version 2 keeps the same extension ID as CORS Unlocker and automatically migrates existing settings.

## Choose a mode

| | Rules mode | Advanced mode |
|---|---|---|
| Engine | `declarativeNetRequest` | Chrome DevTools Protocol `Fetch` |
| Scope | Matching rules | Explicitly attached tab |
| Use for | CORS, headers, redirects, blocking | Inspection, preflight repair, mocks, delay, failures |
| Chrome disclosure | None | Standard debugging banner while attached |

Advanced mode detaches when you switch it off, close the tab, another debugger takes over, or the top-level page navigates to a different origin.

## Rules

A rule contains a page-origin match, request URL glob, optional HTTP methods and resource types, followed by one or more actions.

```json
{
  "name": "Mock project API",
  "enabled": true,
  "match": {
    "initiatorOrigins": ["https://app.example.com"],
    "urlPattern": "https://api.example.com/projects/*",
    "methods": ["GET"],
    "resourceTypes": ["XHR", "Fetch"]
  },
  "actions": [
    {
      "type": "mockResponse",
      "status": 200,
      "headers": { "Content-Type": "application/json" },
      "body": "{\"id\":123,\"state\":\"preview\"}"
    }
  ]
}
```

Available actions are `cors`, `setRequestHeaders`, `setResponseHeaders`, `redirect`, `block`, `mockResponse`, `delay`, and `networkFailure`. Action scripts are validated JSON; arbitrary JavaScript is not evaluated.

## Traffic inspector

Open **Inspect traffic** from the popup, enable Advanced mode for the current HTTP or HTTPS tab, and reproduce the request. The inspector shows method, URL, resource type, outcome, status, duration, matched rules, response headers, and CORS diagnostics. Authorization, Cookie, Proxy-Authorization, and Set-Cookie values are masked by default.

## SDK

The published package remains `cors-unlocker` so existing installs and links continue to work. Version 0.2 adds the Forth Intercept session API while keeping the old CORS helpers as deprecated aliases.

```bash
pnpm add cors-unlocker
```

```ts
import { intercept } from 'cors-unlocker';

const session = await intercept.connect();
console.log(session.origin, session.capabilities);

const status = await session.getStatus();

await session.requestCors({
  credentials: false,
  reason: 'Preview staging API data',
});
```

`requestCors()` always shows an extension-controlled confirmation and applies only to the real top-level page origin. A page cannot request changes for another origin.

### Create a disabled rule draft

```ts
await session.createRuleDraft({
  name: 'Simulate slow projects API',
  urlPattern: 'https://api.example.com/projects/*',
  methods: ['GET'],
  resourceTypes: ['XHR', 'Fetch'],
  actions: [{ type: 'delay', milliseconds: 800 }],
});
```

SDK-created rules are always disabled and scoped to the calling page. By default, the workspace opens so the user can review and enable the draft.

### API surface

- `intercept.connect({ timeout? })` → `InterceptSession`
- `intercept.isAvailable()` → `boolean`
- `intercept.openStorePage()`
- `session.getStatus()`
- `session.requestCors({ credentials?, reason? })`
- `session.disableCors()`
- `session.createRuleDraft(rule, { openWorkspace? })`
- `session.openWorkspace()`

The legacy `isExtInstalled`, `isEnabled`, `enable`, `disable`, `openExtOptions`, and `openStorePage` exports continue to call the new local bridge.

## Upgrade and data

On first v2 startup, Forth Intercept reads `allowedOrigins` and `extConfig`, writes a `legacyBackupV1` recovery snapshot, validates the new `proxyAppState`, and then uses only the v2 state. Old keys are not used as live configuration or dual-written.

The workspace imports old v1 rule exports and complete v2 exports. New exports use the v2 format.

## Limitations

- Chrome only for the v2 release; Firefox support is planned.
- Advanced mode necessarily shows Chrome's debugging disclosure.
- Changes affect matching Chrome traffic, not other applications.
- Forth Intercept does not change your public IP address or decrypt traffic outside Chrome.
