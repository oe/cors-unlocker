# Frequently asked questions

## Is Wireflip a VPN or network proxy?

No. It is a request interception tool inside Chrome and Firefox. It does not route other applications, change your public IP, or provide geographic proxying.

## Why did CORS Unlocker become Wireflip?

CORS repair is now one part of a broader request-lab workflow: observe traffic, change headers, redirect or block requests, return local mocks, and simulate slow or failing APIs. The new name avoids describing the product as only a CORS switch.

## Will my v1 settings survive the update?

Yes. The first v2 startup performs a one-time migration, keeps a local recovery snapshot, and validates the new state. After that, v2 is the only source of truth.

## Why does Chrome show a debugging banner?

Chrome's `debugger` API supports saved Mock, delay and CORS rules, optional recording and temporary tab controls. In 2.1, enabled saved rules automatically prepare matching tabs, so the browser may show its native debugging indicator without recording. Browser-managed header, redirect and blocking actions do not themselves need CDP.

## When does a tab session stop?

Stopping recording clears temporary changes but keeps enabled saved rules running. Disable the rule or its group to stop those changes. Closing a tab releases its attachment, and navigation reconciles rules for the new origin. Chrome’s native Stop pauses execution until Retry; Retry does not start recording. An actual debugger takeover ends the attachment, while DevTools can coexist on browser versions that support it.

## Does Wireflip upload my traffic?

No. Rules stay in extension storage and request logs are kept in the extension service worker's memory. The product has no traffic-upload or analytics endpoint.

## Can it execute JavaScript rules?

Not arbitrary JavaScript. Wireflip accepts validated JSON action scripts. This keeps behavior inspectable and avoids MV3 remote-code and `eval` problems.

## What can a website do through the npm SDK?

It can detect the extension, read its own origin’s status, create disabled drafts and open the workspace. Wireflip 2.1 also supports approved creation and management of a site’s own rules. Website changes need extension-owned approval unless the user manually trusts that exact origin in the popup; credential access still needs confirmation. A site cannot manage manual, unowned or other-origin rules or start recording through the SDK. Capability-check new APIs during rollout.

## Which npm package should I install?

Use `wireflip` and import `{ intercept }`. SDK 2.1.0 is available on npm for the new website-authorization flow. Basic CORS and draft APIs support extension 2.0, while new rule-control APIs require extension 2.1 and capability checks. Firefox 2.1.0 is public; Chrome 2.1.0 is awaiting review. The old hostname and SDK bridge are retained, and migration is optional. See the [migration guide](/migration/) for upgrade steps.

## Is Firefox supported?

Yes. Firefox uses blocking WebRequest rather than Chrome CDP. CORS, headers, redirects, blocking, delay, failure simulation, traffic inspection, the SDK, and response-body replacement are supported. Firefox preserves the server's original HTTP status when replacing a response body, so its static mock behavior is not identical to Chrome.
